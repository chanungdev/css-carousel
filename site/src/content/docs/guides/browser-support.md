기능마다 지원 범위가 다르다. 갈리는 지점을 알고 쓰는 게 낫다.

| 기능 | Chromium | WebKit | Firefox |
|---|---|---|---|
| 스냅·스와이프·레이아웃 | ✅ | ✅ | ✅ |
| loop · autoplay · 썸네일 | ✅ | ✅ | ✅ |
| `::scroll-button()` · `::scroll-marker` | ✅ 135+ | 폴백 | 폴백 |
| 이펙트 프리셋 (scroll-driven) | ✅ | ✅ | ❌ 이펙트 없음 |
| 카운터 | ✅ | ✅ | ❌ 표시 안 함 |

## 두 경로가 같은 것을 만든다

`::scroll-button()`과 `::scroll-marker`를 지원하는 브라우저에서는 버튼·도트·키보드 동작을
브라우저가 만든다. 스크립트는 인덱스 추적 외에 관여하지 않는다.

지원하지 않는 브라우저에서는 스크립트가 같은 역할을 하는 버튼과 `tablist` 마커를 주입한다.
두 경로는 **같은 CSS 변수를 읽는다** — 테마를 한 번 쓰면 양쪽에 적용된다.

어느 경로로 돌고 있는지는 이렇게 확인한다.

```js
CSS.supports('selector(::scroll-marker)');
```

## 알려진 한계

- RTL은 기본 구성(한 화면 한 장)에서 `data-carousel-loop` 포함 동작한다. 다중 아이템 RTL은
  검증하지 않았다.
- `refresh()`는 loop 캐러셀의 `setSize`를 다시 계산하지 않고 폴백 마커·버튼도 다시 만들지
  않는다. 슬라이드 수가 바뀌면 `destroy()` 후 다시 `init()`한다.
- 카운터는 `container-type`을 건 루트에서 스크롤러에 그려야 맞는 값이 나온다. 라이브러리가
  이미 그렇게 하므로 직접 옮기지만 않으면 된다.
