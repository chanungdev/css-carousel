`data-carousel-pages`를 붙이면 한 장씩이 아니라 **한 화면씩** 넘긴다. 마크업은 평평한 목록
그대로다 — 브라우저가 multicol로 나누므로 목록을 여섯 개씩 끊어 둘 필요가 없다.

<Demo
  html={carousel('data-carousel data-carousel-pages class="grid"', 12)}
  css={`.grid {
  --carousel-items: 3;        /* 한 줄에 셋 */
  --carousel-gap: 0.75rem;
  --carousel-page-block: 23rem;
}`}
/>

줄 수는 높이가 정한다. `--carousel-page-block`을 한 줄 높이로 나눈 만큼 들어간다. 한 줄에 셋,
두 줄이 들어가는 높이면 페이지당 여섯이다.

## 페이지 경계에서만 멈춘다

스냅 대상은 페이지 하나뿐이고 슬라이드 쪽 정렬은 꺼 둔다. 둘 다 대상으로 남으면 드래그가 카드
경계에 멈춰 앞 페이지 끝과 다음 페이지 앞이 한 화면에 섞인다. `::column`이 없는 브라우저에는
스냅 대상 자체가 없으므로, 폴백 스크립트가 스크롤이 멈춘 뒤 가장 가까운 페이지로 맞춘다.

## 페이지가 기준이 된다

마커는 슬라이드가 아니라 페이지마다 하나다. 위 데모는 카드가 12장이지만 마커는 2개다.
`::column`을 지원하는 브라우저에서는 브라우저가 직접 만들고, 그렇지 않으면 폴백 스크립트가 같은
수를 만든다. `next()`·`prev()`·`goTo()`도 한 페이지씩 움직이고 `index`는 페이지 번호다.

`pageCount`는 브라우저가 몇 페이지로 나눴는지를 레이아웃에서 되읽는 값이다. 그래서 창 크기나
줄 수가 바뀌면 따라 바뀌고, 폴백 마커도 그때 다시 만들어진다.

## 왜 float인가

컬럼 안은 일반 흐름이라 블록 요소는 세로로 쌓인다. 가로로 늘어놓으려면 inline-level이거나
float여야 하는데, inline-level은 태그 사이 줄바꿈 공백이 한 줄에 한 자리를 먹는다 — 셋이 들어갈
자리에 둘만 들어간다. float에는 그 문제가 없다.

## 카운터는 나오지 않는다

CSS counter는 슬라이드가 올리는데 이 모드에서 세어야 할 것은 페이지다. 컬럼은 counter를 올릴 수
없어 CSS만으로 맞출 방법이 없다. `1 / 2` 대신 `1 / 12`가 나오느니 아예 내지 않는다.
